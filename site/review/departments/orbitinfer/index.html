Topology-Aware Data Movement for Disaggregated GPU Inference

面向解耦式 GPU 推理的拓扑感知数据搬移

系统依据 NVLink、PCIe、InfiniBand、跨数据中心网络和 CXL 层级选择传输路径，并将逐层 KV 传输与预填充重叠。

问题
Prefill 与 Decode 分离后，每个请求都要搬移大体量 KV Cache，而统一使用 RDMA 会忽略不同 GPU 物理关系造成的数量级带宽差异。
方法
方案在启动时发现互连层级，按传输选择最合适的通道；同时使用逐层流水传输、面向 MoE 的 NVLink 域放置，以及作为共享溢出层的 CXL 3.0 内存扩展器。
结果
论文以 70B 模型每请求约 1.3GB KV 为例，分析显示逐层流水可隐藏 76%—100% 的传输时间，跨三类架构预计比统一 RDMA 降低 3—18 倍传输时延。
证据与局限
  • arXiv v2 摘要和本地获取的论文正文给出 1.3GB/request、72 倍互连带宽差异及流水隐藏比例
  • 正文将 3—18 倍结果明确描述为跨三类架构的投影分析

局限：尚未在同时具备异构互连和 CXL 3.0 的多节点集群上完成端到端实测；星间链路的长时延、断续性和能耗约束需要重新建模，不能直接套用数据中心参数

部门意义

OrbitInfer 可把链路类型、拓扑距离和缓存层级纳入 PD 分离调度器，并用逐层传输而不是整请求搬移作为 OrbitServe 的首个对照基线。

Bole: Efficient Tree Speculation for Hybrid-Attention Language Models

Bole：混合注意力语言模型的高效树状推测解码

Bole 将线性注意力递推改写为树结构闭式计算，只保存 token 级状态因子，并在采样后重建被选中的单一路径。

问题
现有树状推测解码围绕全注意力 KV Cache 设计，在混合注意力模型上需要逐分支遍历递归层并为每个候选节点物化完整状态，导致验证时延和瞬时显存快速增长。
方法
系统通过树结构闭式递推和专用 GPU Kernel 并行验证所有候选节点，以无损 token 因子编码状态更新，并在 SGLang 中按整批前向成本动态分配验证预算。
结果
摘要报告线性注意力树验证加速 3.4—7.7 倍、瞬时状态内存减少 82—99 倍；离线吞吐相对自回归最高 4.72 倍，在线 TTFT 和 TPOT 相对最强树推测基线最多下降 67.6% 和 49.9%。
证据与局限
  • arXiv 官方摘要给出四种模型、两类 GPU 和在线代理负载上的主要指标
  • 摘要明确说明系统已集成 SGLang，并区分自回归基线和最强树推测基线

局限：当前核验主要依据摘要，尚未逐表复核不同模型和批量规模的完整结果；收益依赖混合注意力状态结构，不代表全注意力模型也能获得相同提升

部门意义

OrbitInfer 应把递归状态而非只有 KV Cache 纳入混合注意力模型的星载内存模型，并评估状态因子化对显存峰值和批量调度的共同收益。

Heterogeneous LLM Serving with General-Purpose Processing-Near-Memory for Retrieval-Based Sparse Attention

KARAT：面向检索式稀疏注意力的通用近存计算节点

方案让 GPU 保存权重并执行投影与 MoE，让大容量 PNM 节点保存 KV 和索引并执行所有读缓存操作。

问题
百万 token 上下文把 KV Cache 和检索索引推到 GPU 显存之外，而既有固定功能 PIM/PNM 难以同时承载不断变化的索引器和稀疏注意力算法。
方法
KARAT 以 LPDDR 大容量和通用计算覆盖检索索引器，并使用细粒度机会式微批调度隐藏专家通信，再按上下文长度重平衡两个设备侧的 token 数量。
结果
摘要报告在三种模型和真实代理轨迹上，相对 GPU-only 基线的 SLO 约束吞吐/TDP 提升 2.09—6.13 倍，对免训练稀疏注意力方法提升 1.36—3.21 倍。
证据与局限
  • arXiv 官方摘要给出设备分工、两种调度机制和三模型评估区间

局限：当前核验基于摘要，PNM 硬件成本、实现面积和端到端互连开销需从正文复核；针对百万 token 检索式稀疏注意力，不能直接代表普通全注意力工作负载

部门意义

OrbitInfer 可借鉴其按操作类型拆分的思路，把 KV/索引常驻节点映射为星上存储计算单元，并在仿真中加入上下文长度感知的微批平衡。

NVLLM: A 3D NAND-Centric Architecture Enabling Edge on-Device LLM Inference

NVLLM：以 3D NAND 为中心的端侧大模型推理架构

架构在 Flash 内直接执行 FFN 点积，把注意力和 KV 调度留给轻量 CMOS 与外部 DRAM，避免权重先搬入 DRAM。

问题
端侧单批解码受模型权重容量和带宽限制，传统 GPU 外存推理及 SSD 加速器仍需经过 DRAM 搬移权重，无法充分利用高密度 NAND。
方法
NVLLM 通过晶圆级堆叠整合多平面 3D NAND、乱序点积处理通道、ECC 和缓冲区，直接对原始 NAND 读取执行 GEMM/GEMV；KV 感知调度随上下文增长维持流水。
结果
论文在 OPT 和 LLaMA、最高 30B 参数配置上报告：相对 A800 外存推理加速 16.7—37.9 倍，相对 SSD 类设计最高 4.7 倍，CMOS 面积开销约 2.7%。
证据与局限
  • arXiv v2 摘要与本地获取正文提供模型范围、两类基线和面积开销
  • 正文明确区分 NAND 内 FFN 与 CMOS/DRAM 侧注意力路径

局限：依赖定制 3D NAND 与晶圆堆叠，不能直接部署到现成通用星载计算平台；需进一步验证 NAND 耐久性、辐射可靠性和持续推理时的热设计

部门意义

OrbitInfer 可把 NVLLM 作为高容量低带宽存储计算的上界设计，重点评估 FFN 权重下沉、ECC 和 KV 调度在星载可靠性约束下的可行性。

A CXL Memory Rack for Multi-Turn LLM Serving

HyMCache：用于多轮大模型服务的 CXL 混合内存机架

系统以小容量设备 DRAM 缓存热点、以 SSD 承载 TB 级 KV，并利用前缀预取和机会式写缓冲适配多轮请求的只读、可预测、追加式访问。

问题
多轮和代理式请求希望复用历史 KV，但 GPU HBM 和主机 DRAM 难以经济地扩展到 TB 级共享容量，纯 SSD 又难以满足时延要求。
方法
HyMCache 在 CXL 接口后组合设备 DRAM 与 SSD，根据请求前缀提前把关键 KV 读入 DRAM，并把追加写入机会式缓冲，从而用少量 DRAM 覆盖延迟敏感访问。
结果
真实 CXL-HM 原型在相同 DRAM 预算下，相对本地 LMCache 在单节点提升 3.0 倍、在 PD 分离服务提升 1.45 倍；相对 1TB 分布式 DRAM Mooncake 性能低约 30%，但 DRAM 用量减少 16 倍。
证据与局限
  • arXiv 最新版本摘要和本地正文给出真实原型、LMCache 与 Mooncake 对照数据

局限：CXL 机架内互连条件优于星间链路，远程 KV 层级需要替换时延与故障模型；对 Mooncake 的性能差距说明低成本层不能完全替代高带宽 DRAM

部门意义

OrbitInfer 可用该结果建立 KV 共享层的成本—时延基线，并把前缀预取、写缓冲及断链恢复加入星间分层缓存实验。

WitCert: Sound Runtime Risk Observability and Gating for KV-Cache Quantization

WitCert：KV Cache 量化的运行时风险证书与门控

系统为每层、每头、每步计算精确与压缩注意力总变差的上界，并在风险升高时按证书或见证值选择性修复缓存。

问题
离线基准平均分无法告诉在线服务某一个请求是否正被 KV 量化破坏，部署系统缺乏可观测、可门控的请求级质量风险指标。
方法
WitCert 提供适用于黑盒量化器的确定性带范数见证上界，以及带请求级失败预算的受控抖动 INT8 概率证书；二者接入 SGLang 后驱动风险排序和选择性修复。
结果
摘要报告门控把 hard RULER 上 raw-cast FP8 得分从 22.8 恢复到 79.7，与未压缩差异的配对区间为 +0.0 至 +0.8；认证 INT8 在同等内存下可服务 1.88 倍 KV token。
证据与局限
  • arXiv 最新版本摘要和本地正文给出 RULER、内存容量及 SGLang 接入结果
  • 论文明确区分自适应安全的确定性界与仅适用于非自适应查询的概率证书

局限：确定性界可能偏保守，概率证书对量化器和查询适应性有明确前提；摘要中的质量恢复集中在 hard RULER，仍需覆盖目标模型和星载任务

部门意义

OrbitInfer 可把 WitCert 式风险计量器放在自适应 KV 精度策略之前，在内存紧张时只压缩低风险层头，并为高风险请求保留回退路径。

EdgeXpert: An Edge Device for Memory-Efficient LLM Inference with Mixture-of-Experts and Speculative Decoding

EdgeXpert：协同 MoE 与推测解码的端侧推理设备

系统在 Prefill 阶段复用提示级专家集合，在 Decode 阶段合并同深度候选 token 的专家通道，以减少外部存储访问。

问题
MoE 通过稀疏激活减少单步计算，推测解码通过一次验证多个 token 减少步数，但二者组合会扩大候选 token 的专家权重并集，使外存访问重新成为瓶颈。
方法
Prefill 使用轻量编码器选出重要 token 并构造共享专家集合；Decode 按树深合并候选所需专家，只载入显著通道，再用计算校准补偿被省略通道。
结果
论文摘要称在 Samsung 28nm、800MHz 综合配置下，相对既有方案最高降低 56.3% 时延和 44.1% 能耗，同时维持接近基线的准确率。
证据与局限
  • arXiv 官方摘要给出机制、28nm 综合条件和时延、能耗指标

局限：结果来自芯片综合而非流片设备实测；摘要没有给出这里所需的完整模型规模、外存配置和精度退化表

部门意义

OrbitInfer 可把专家权重外存访问量加入星载推测解码评估，重点验证提示级路由复用是否能在受限内存带宽下稳定降低能耗。

SHIELD: A Segmented Hierarchical Memory Architecture for Energy-Efficient LLM Inference on Edge NPUs

SHIELD：面向端侧 NPU 的分段分层 eDRAM

方案分离 BF16 的符号、指数和尾数，对瞬时 QO 尾数关闭刷新、对持久 KV 尾数放宽刷新，以利用不同生命周期和误差敏感度。

问题
端侧 NPU 需要高密度 eDRAM 保存激活与 KV，但周期刷新消耗显著能量；既有研究更多优化持久 KV，忽略短生命周期 QO 激活的可容错性。
方法
SHIELD 按数据类型和 BF16 字段分段管理 eDRAM：保护高敏感符号和指数，对瞬时 Query/Output 尾数不刷新，对长期 KV 尾数使用更宽松刷新周期。
结果
摘要与正文报告相对标准刷新基线降低 35% eDRAM 刷新能源，并在 WikiText-2、PIQA 和 ARC-Easy 上保持准确率。
证据与局限
  • arXiv v2 摘要和本地正文明确给出 35% 刷新能源降幅及三个验证任务

局限：指标聚焦 eDRAM 刷新部分，不等同于整机总能耗下降 35%；辐射环境可能改变允许的刷新松弛和位错误边界

部门意义

OrbitInfer 应把激活类型和位级可靠性加入存储能耗模型，并在辐射注错条件下重新测定 QO 与 KV 的可放宽刷新范围。

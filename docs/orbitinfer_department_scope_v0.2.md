# 星载大模型推理引擎部门周报范围草案 v0.2

> 本草案只定义 weekly paper survey 的内容范围、信息分层和顶会覆盖，不定义产品研发计划、实验方案或工程里程碑。

## 1. 部门方向名称

**星载大模型推理引擎**

周报关注：

> 大模型推理引擎及其在星载、边缘、实时、功耗受限、存储受限、可靠性受限和动态通信环境中的最新研究、顶会论文、重要论文、开源框架、Benchmark、数据集与产业进展。

“星载”是重点应用约束，但检索不能只看标题中含有 satellite / spaceborne 的论文。大量可迁移的重要成果首先发表在 ML Systems、系统、体系结构、实时系统和边缘计算领域。

## 2. 周报内容边界

### 2.1 核心方向：默认持续覆盖

1. **LLM / VLM / MoE 推理引擎**
   - serving runtime、执行引擎、model runner；
   - continuous batching、prefill/decode、并行执行；
   - SGLang、vLLM、TensorRT-LLM、llama.cpp、KTransformers 等框架的重要版本和机制变化。

2. **推理调度与资源编排**
   - 请求调度、优先级、deadline、抢占、迁移；
   - prefill/decode 调度与解耦；
   - 动态功率预算、温度和能源约束下的自适应调度；
   - latency、throughput、energy、quality、任务价值之间的权衡。

3. **KV Cache 与存储系统**
   - KV Cache 分页、压缩、量化、稀疏化、淘汰与迁移；
   - 权重、KV Cache、MoE 专家在 HBM / DRAM / SSD 间的放置、预取和 offload；
   - 分层存储、异构内存和 IO 优化。

4. **MoE 推理系统**
   - expert placement、expert parallel、route-aware prefetch；
   - 热/冷专家管理、异构执行、专家裁剪和缓存；
   - MoE 在受限设备、边缘设备和分布式环境中的部署。

5. **模型压缩与自适应精度**
   - 权重、激活和 KV Cache 量化；
   - 动态量化、混合精度、任务感知和功耗感知精度切换；
   - 剪枝、蒸馏、稀疏化等对推理引擎有直接影响的工作。

6. **可靠推理与容错**
   - soft error、fault injection、异常检测；
   - checkpoint、rollback、recomputation、选择性保护；
   - GPU/NPU/存储错误对 LLM/VLM/MoE 推理的影响。

7. **边缘、端侧与实时大模型**
   - edge/on-device LLM、embedded AI、实时推理；
   - 资源受限设备上的 runtime、调度、量化和存储；
   - 可迁移到星载环境的低功耗、低内存和高可靠性机制。

8. **分布式与多节点推理**
   - tensor/pipeline/expert parallel；
   - 请求、模型、KV Cache 和专家迁移；
   - 网络感知的模型切分、放置和分布式推理；
   - 可扩展到星间协同的通信与调度方法。

### 2.2 强相关邻近方向：有重要进展时纳入

- AI 加速器、GPU/NPU/FPGA、HBM/CXL 和新型存储；
- 低功耗体系结构、energy-efficient computing；
- 实时系统、energy-aware scheduling、thermal-aware scheduling；
- 星载计算、在轨智能、航天器自主系统；
- 卫星网络、星间链路、DTN 和边缘网络；
- 辐射环境、器件可靠性和体系结构级容错；
- 遥感 VLM、星载多模态感知，但必须包含推理系统或部署价值；
- 训练/推理一体化系统，但必须对 inference/runtime 有直接参考价值。

### 2.3 默认不进入正文

- 与部署、系统和推理效率无关的通用模型能力论文；
- 普通 prompt、Agent 应用和模型排行榜；
- 纯训练算法且没有推理侧影响的论文；
- 只有应用精度、没有系统或部署贡献的遥感论文；
- 没有技术证据的“星载大模型”概念稿和营销稿；
- 纯航天器电源、热控、轨道或任务规划研究；
- 仅因最近七天上传 arXiv、但没有顶会身份、重要作者、显著影响或项目相关性的普通论文。

## 3. 周报重点信息类型

### 3.1 本周最新进展

- 顶会新录用论文、Best Paper、Distinguished Paper 和重要 Oral/Spotlight；
- 已发表重要论文的新版本，尤其是方法、实验、开源代码或结论发生实质变化；
- 重要研究团队、实验室和公司发布的新系统；
- SGLang、vLLM、KTransformers、TensorRT-LLM 等重要框架版本；
- 新 Benchmark、数据集、推理评测方法和硬件测量工具；
- 对星载大模型推理有直接启发的产业、芯片和航天工程进展；
- 权威公众号、实验室博客和技术综述中的趋势判断，事实必须回到论文、代码或官方来源验证。

### 3.2 顶会论文

顶会论文不要求发生在最近七天。周报同时维护：

- 最近一周公布、录用或受到广泛关注的顶会论文；
- 最近两年与本部门直接相关的顶会论文固定库；
- 更早但构成当前技术路线基础的经典论文；
- 顶会论文的新代码、新实验、新版本和后续工作。

### 3.3 重要非顶会论文

最近七天的非顶会论文只有满足以下条件之一才进入正文：

- 知名团队、重要作者或头部公司发布；
- 提出明显的新系统、新 Benchmark 或开源框架；
- 在推理引擎、动态功率调度、KV Cache、MoE、量化或可靠性上有明确突破；
- 与 OrbitInfer 当前方向高度相关；
- 已经获得显著社区关注、复现或产业采用；
- 是重要论文的实质性新版本。

其余论文进入数据库，不占用研究员的主要阅读时间。

## 8. 内容排序标准

每条信息按以下因素综合排序：

1. 是否为顶会或重要论文；
2. 是否代表领域趋势变化；
3. 是否有可信实验、代码或 Artifact；
4. 是否产生新 Benchmark、数据集或开源框架；
5. 是否与星载大模型推理引擎直接相关；
6. 是否是重要论文的实质性新版本；
7. 是否影响 SGLang、vLLM、KTransformers 等技术路线；
8. 是否具备产业采用或真实部署信号。

不因为“发布日期新”自动获得高优先级，也不因为论文不在本周发表就排除重要顶会论文。

## 9. 周报信息来源

周报采用“原始证据 + 权威解读 + 行业信号”三层信息结构。公众号是重要的趋势发现和论文解读来源，但不替代论文、会议官网、代码仓库和项目公告。

### 9.1 第一层：论文与会议原始来源

作为论文身份、发表状态和实验结论的主要依据：

- 顶会官网、正式 proceedings 和会议日程；
- arXiv；
- OpenReview；
- DOI / Crossref；
- 论文作者或实验室项目主页；
- ACM Digital Library、IEEE Xplore、USENIX Proceedings；
- Artifact Evaluation 页面和正式补充材料。

论文是否属于顶会、论文版本、作者、实验结果和发表时间，必须以这一层为准。

### 9.2 第二层：代码、框架、Benchmark 与数据集

作为开源状态、工程进展和社区采用情况的主要依据：

- GitHub 官方仓库、Release、Tag 和重要设计文档；
- Hugging Face 模型、数据集和 Space；
- Papers with Code；
- SGLang、vLLM、KTransformers、TensorRT-LLM 等官方项目；
- MLPerf及其他权威Benchmark官网；
- 公司、研究机构和实验室官方技术博客。

公众号提到框架性能、新版本或开源状态时，需要回到这一层核验。

#### 公众号文章采集

固定池不做全网盲搜，按账号获取最近更新：

1. 定时获取每个账号的新文章列表；
2. 保存标题、公众号、作者、发布日期和原文链接；
3. 获取可访问的正文并生成结构化文章卡；
4. 识别文章提到的论文、会议、框架、Benchmark和研究团队；
5. 与论文库、框架库和本周候选去重；
6. 回到论文、顶会官网、GitHub或官方博客核验；
7. 通过审阅后进入“趋势综述”“论文解读”或相应技术板块。

正文无法自动获取时，保留元数据并进入待补队列，可通过已登录Chrome或人工投递原文链接补齐；不得根据标题直接生成内容判断。

#### 公众号文章审阅标准

优先纳入：

- 串联多篇重要论文并形成清晰技术趋势；
- 对顶会论文给出有价值的比较、背景或局限分析；
- 披露重要新框架、Benchmark、数据集或工程系统；
- 来自重要实验室、研究机构或头部公司；
- 提供论文原文之外的作者访谈、工程经验或产业采用信息；
- 与推理引擎、KV Cache、MoE、量化、功耗、可靠性或边缘部署强相关。

默认降权或排除：

- 单篇论文摘要翻译且没有新增解读；
- 没有原始链接或技术证据的性能宣传；
- 泛模型发布、Agent应用和产品体验；
- 课程、活动、招聘和广告；
- 多个公众号重复转载的同一内容；
- 与星载大模型推理引擎方向弱相关的热点文章。

`PaperWeekly`等论文解读文章采用“论文主记录 + 解读附件”的方式入库：

- 论文事实保存在论文库；
- PaperWeekly文章记录为 `interpretation_source`；
- 保存其重点解读、技术比较和适合中文读者的说明；
- 不把同一篇论文重复计为“论文”和“公众号事件”两项。

# 周报输出模板

本文件在事件库已建立、S/A 级事件已完成初步复核后使用。

默认语言：中文。英文公司名、source 名、项目名和技术术语按行业常用写法保留。

## 输出模式

生成完整周报前必须确认已导入企查查/融资/工商变更清单。若缺少该文件，不输出完整融资模块；只有在用户明确确认跳过 `Manual_Import` 时，才可生成”公开信息草稿版”，并在标题块或摘要中标明”手工融资数据缺失”。

### 完整版与事件表（数据库版）的关系

三种输出版本承担不同角色，**完整版不是全量信息**：

| 版本 | 角色 | 事件覆盖 | 字段粒度 |
|---|---|---|---|
| 老板版 | 一页纸决策简报 | 常规编辑基线 5-8 条；强相关 S/A 全量纳入、数量不限 | 紧凑五段式 |
| 完整版 | 决策稿（对外/内部交付） | S/A 全部 + 部分 B | 6-9 列：事件描述 + 关联判断 + 主来源 |
| 数据库版（事件表） | 全量底库 / 检索 / 沉淀 | S/A/B/C 全部，含未入正文 | 26 列：含 3 维分数、`meaning_for_us`、`next_watch`、`analyst_note`、`source_tier`、`source_discovery_flag` 等 |

事件分配规则：

- **S 级**：必进完整版正文 + 事件表。**融资板块 S 级原则上必进**，但若融资占比超过 30%，按 `reporting-playbook.md` 融资压减规则保留最关键 S 级（金额最大、路径最清晰、头部战略融资优先），其余转 `Database_Only` 进数据库版或"全量融资附录"。**禁止用大量评 S 绕过 30% 上限**——评 S 后仍超限属评级偏松，需回阶段 4 复核。
- **A 级**：默认进完整版正文 + 事件表；**融资板块的 A 级仍受"融资占比 ≤ 30% HARD RULE"与融资压减优先级约束**（参 `reporting-playbook.md`），未进正文的融资 A 级标 `Database_Only` 保留在数据库版。
- **B 级**：默认仅入事件表；如该模块行数未到篇幅建议下限，或 B 级承担明显的趋势补充作用，可补进完整版相应板块表尾。
- **C 级**：仅入事件表，不进入完整版任何位置。

完整版缺失但事件表保留的字段：3 维评分（`space_compute_relevance_score` / `industry_impact_score` / `novelty_score` / `total_score`）、`meaning_for_us`、`next_watch`、`analyst_note`、`source_tier`、`source_discovery_flag`、`secondary_sources`（除非格内分号写出）。需要回溯评分依据、对我们公司的具体意义或下周一对一跟踪点时，必须查事件表，不能只看完整版。

完整版每周表格行数有 `篇幅建议` 下限（合规阈值与各板块下限见 `reporting-playbook.md` 回归基准段）；B 级事件可补充进正文以达到模块下限，C 级仅入事件表。事件表是底库，行数通常 1.5-3 倍于完整版。W16 仅作为高密度周容量参照（事件表 100+），其融资 41/78 ≈ 53% 在新口径下属于反例，不得复刻。

**篇幅下限不是上限**：当周事件密集时（如出现重大并购、立法节点、密集发射），完整版正文应优于"压缩到模板上限"做"完整呈现"。`reporting-playbook.md` 的金额兜底规则（≥1 亿美元 / 5 亿元的融资优先入正文，≥10 亿美元 / 100 亿元的并购强制入正文，立法事件强制入正文）高于板块下限，但**金额兜底仍受"融资占比 ≤ 30% HARD RULE"约束**——融资条目超过正文 × 30% 时，按 `reporting-playbook.md` 的融资压减优先级保留最重要条目，其余转 `Database_Only`，除非用户明确要求"全量融资附录"才允许超出 30%。立法 / 大型并购（≥10 亿美元 / 100 亿元）属政策板块，不计入融资占比。

**容量参照（不是合规模板）**：W16 正文 78 条仅说明高密度周可达的事件量级；其融资 41/78 ≈ 53% 在新口径下属于反例。**合规阈值与不达标根因表见 `reporting-playbook.md` 的"回归基准（Regression Baseline）与质量阈值"段**（合规口径：正文 ≥ 70 / 事件表 ≥ 80 / 融资 ≤ 30%），本文件不重复，**不得用 W16 的具体板块构成（17/20/41）作为合规证据**。

### 老板版

用于一页纸决策简报。

```markdown
# 太空算力产业周报｜老板版

时间窗口：YYYY.MM.DD - YYYY.MM.DD
整理日期：YYYY.MM.DD

## 1. 本周最重要的三句话

1. **政策：** ...
2. **科技：** ...
3. **融资：** ...

## 2. S/A 级重点事件

| 优先级 | 事件 | 判断 | 对我们的意义 | 后续跟踪 |
|---|---|---|---|---|
| S | ... | ... | ... | ... |

## 3. 风险/机会提示

- **机会：** ...
- **风险：** ...
- **下周必须看：** ...
```

### 老板版HTML

用于一页纸决策简报的网页化呈现。**不是完整版的 HTML 化**——常规编辑基线为 5-8 条，但所有强相关 S/A 必须全量进入核心区、数量不限。融资事件默认精选 2 条；直接命中太空算力主航道或关键链路的 S/A 融资不受该配额限制。一般商业航天和外圈事件仍需编辑筛选，不能因为取消强相关上限而全部塞入。

“老板版”仅用于内部版本分类与保存文件名，不属于对外展示文案。HTML `<title>` 以及任何 `og:title` / `twitter:title` 必须写为 `中美太空算力周报 · YYYY-Wxx`，页面 masthead 与分享摘要同样不得出现“老板版”。

本节只定义**内容、结构、事件选择、融资约束、保存路径与内容相关自检**。颜色 / 字体 / 间距 / 形状 / dark card / Hard Rules 等视觉规范以 `references/boss-html-design.md` 为唯一源——加载顺序：先读本节确定"写什么"，再读 boss-html-design 确定"长什么样"。生成后**内容自检看本节末尾清单，视觉自检看 boss-html-design.md Hard Rules**。

**默认母版**：`assets/老板版_2026-W23.html`。后续老板版必须继承其 CSS、DOM 类名、首屏比例、proof 双栏、card 节奏和三栏行动备忘；不得重新写一套“接近 W23”的精简 CSS。`assets/老板版_2026-W20.html` 仅保留为旧实例参考。详细契约与验证见 `references/w23-boss-html-baseline.md`。

#### 文档结构（顺序固定）

每节只列"内容职责"，节内字号 / 字体 / 颜色 / padding 等视觉数值见 `boss-html-design.md` 的 type scale 表与 spacing tokens；本节不重复。


1. **Masthead**
   - 左：报告名 `中美太空算力周报`
   - 右：周报编号 `YYYY-Wxx` + 时间窗口 `YYYY.MM.DD–YYYY.MM.DD` + 整理日期 `Compiled YYYY.MM.DD`
   - 下方一行扫描完整度提示。例："Pass A/B/C 全部完成"或"注意：境外融资清单缺失，本期不含 5C 境外条目"。
2. **Executive hero**（首屏判断 + 指标 rail + proof object）
   - 左侧：50-90 字一句总判断；必须用“本周事实锚点 → 阶段判断 → 证伪条件”组织，不能只写“仍待验证”之类通用结尾。选 1-2 个判断关键词加 terracotta 下划线。
   - 右侧或下方：3-5 个关键指标组成 metric rail，必须显示融资占比并标明分母。完整版已通过 gate 时写 `融资占正文 X%`；只有老板版 cards 可用时写 `核心 cards 融资占比 X%`，禁止混用。其余可选 `事件表 N` / `正文 N` / `S/A N` / `政策-科技-融资 split`。
   - 同屏必须有一个 proof object：timeline strip、ranked signal list、capital strip、regulatory ledger 或 source-confidence line。不能只有大标题和段落。
   - dark card 是否使用见 boss-html-design.md（全页 ≤ 1）。
3. **Proof object 内的上周重点延伸**
   - 直接并入 proof object 底部，作为本周信号链之后的延伸；不设置“上周回顾”标题，不创建独立 section 或独立大框。
   - 只回顾紧邻上一周 `W(n-1)`；从上一周 `w{n-1}-reports` 内的真实周报提炼，不回溯更早周次。
   - 只写一个 `上周重点：`，正文用一段较完整摘要概括上一周最重要的产业变化，并点名支撑摘要的关键主体与动作。
   - 摘要后放置 `<!-- PREVIOUS_WEEK_BUTTON -->`。按钮必须位于正常文档流中，随摘要长度自然移动；禁止 `position:absolute/fixed` 和固定高度容器。
   - GitHub Pages 构建生成仅跨一期的双向导航：最新 `index.html` 显示 `← W(n-1) 周报`；紧邻上一周历史页在同一位置显示 `W(n) 周报 →` 并返回 `index.html`；更早历史页不显示按钮。每次构建先清理旧的生成导航，再注入新的相邻周关系。
   - 两个按钮都必须是带真实 `href` 的 `<a>`，使用相对路径；采用核心事件卡片形状：`ivory-deep` 背景、1px `light-gray` 边框、8px 圆角、紧凑 padding，无阴影、非 pill。默认无下划线，hover 时文字和边框变为 `terracotta`，并提供清晰的 `focus-visible` outline。
   - 不写“本周进展”、问题核验、评分标签或置信度；不为了形成连续叙事而加入上一周文件中没有的事实或判断。
   - 如果上一周文件缺失，省略摘要且不注入按钮，并在交付说明中明确缺失；不得编造或使用 `#` 占位。周次必须归属正确：W28 页面回顾 W27，不能把 W28 事件写入回顾。
4. **三条主线**（政策 / 科技 / 融资）
   - 必须使用不同信息形态（card family 见 boss-html-design.md "Allowed Card Families"），不能都是 prose：政策→ timeline / regulatory ledger；科技→ milestone ladder / evidence stack；融资→ capital strip / sector mix row。
   - 每条主线 60-100 字判断，文字必须绑定到可扫读的证据形态。
5. **Core event dossier：常规编辑基线 5-8 条，强相关 S/A 全量纳入且数量不限**
   - 至少使用 3 种 card family（具体可用清单见 boss-html-design.md），同一种 ≤ 3 张。
   - 每个事件必须有一个视觉锚点：金额、日期、机构、法案号、任务名、芯片/处理器名、发射器、客户、轨道、source tier 或 next trigger。
   - 顶部 metadata row 内容：`优先级 S/A · 板块 政策/科技/融资 · 国家 中国/美国/跨国 · 事件日期 M/D`。
   - 标题 H3：事件一句话。
   - 下面四段紧凑展开（不分小标题，段首三个字加粗充当结构提示）：
     - **判断**：这条说明什么。
     - **影响**：对产业 / 政策 / 资本路径的传导。
     - **对我们的意义**：明确动作落点。
     - **后续跟踪**：1-2 个观察对象 + 可观察指标 + 触发条件；禁止用“跟踪后续公告、监管文件、合同落地或技术验证结果”作为任何 card 的通用占位句。
   - footer：`Source: <来源名> ↗`，**必须是可点击的 `<a href="<source_url>" target="_blank" rel="noopener noreferrer">Source: <来源名> ↗</a>`**——视觉规范见 `boss-html-design.md` Source Links (HARD MANDATORY) 段。
6. **融资补充摘要**（条件性出现）
   - 当本期融资事件数 > 2 时必须出现，作为 cards 之后单独一段（**非 card** 形式）。
   - H2 `融资其余条目`。
   - **一段完整叙述**（180-320 字，W23 密度），先写原始清单 → 筛入数量（境内 A→B、境外 C→D），再扣除上方融资 cards，按行业聚合剩余的芯片/半导体、商业航天/卫星、AI 算力条数与金额区间。金额原币置前并给出 RMB/USD 对照值；结尾指向数据库版或融资筛选审计表。三个行业类别及条数用 `<b>` 强调。
   - **不列表 / 不出表格 / 不出公司名清单**。意图是"指向数据库版"，不是"二次浓缩列表"。
7. **底部三栏 Action memo**（固定结构）
   - 三列等宽：`机会` / `风险` / `下周必须看`。
   - 每列 2-4 条，无 bullet，条目间 hairline 分隔。每条 50-80 字。
8. **Colophon**（页脚）
   - 一行：`中美太空算力周报 · YYYY-Wxx · Compiled YYYY.MM.DD · Internal use`
   - 不放 logo / 社交图标 / CTA / 版权年份循环。

#### 事件选择与融资约束

- 常规编辑基线 5-8 条（普通周通常 5-6）；所有额外 S/A 中，凡直接改变主航道判断、提供关键在轨/商业/政策证据，或直接涉及太空算力、太空数据、星载AI、能源、关键链路与可调用服务者，必须全部纳入且无数量上限。不得用 B/C 或一般商业航天弱相关事件增加数量。
- 核心 cards 先完整展示 S，再展示 A；每个评级层内部按事件日期升序，同一天内按 `政策 → 科技 → 融资` 分组。同类 cards 上下相邻但保持一事一卡；同级同日同类组内按总分与证据强度排序。
- **融资事件常规精选 ≤ 2 条**；所有直接命中太空算力主航道或关键链路的强相关 S/A 融资必须进入核心区，不受该默认配额限制。一般融资只有以下三个理由可以突破常规配额：
  1. 事件评级为 **S**（且经过阶段 4 复核未被 30% HARD RULE 压减）；
  2. 触发境外 ≥ 10 亿美元 / 境内 ≥ 100 亿元的并购/IPO **金额兜底**；
  3. 头部太空算力公司战略融资 / 国家队入股 / 关键政府客户绑定 → **战略兜底**。
- 不设强相关融资 cards 的数量上限；一般融资仍应克制，其余进“融资补充摘要”段。
- 政策事件优先纳入立法 / 出口管制 / 频谱监管；科技事件优先纳入轨道里程碑 / 星上算力实证 / 头部产品节点。
- card 之外的融资只允许以“融资其余条目”一段行业聚合摘要出现，不在 HTML 中逐笔列公司；逐笔清单留给数据库版和独立《本周融资》。

#### 事件 card 的源链接（HARD RULE）

老板版 HTML 是供管理层一页扫读的简报。一般 event card 必须能点开原文；企查查高相关融资按下述例外处理。

**1. 必带 source_url，作为 card 选取硬条件**

- 进入常规 cards 候选名单的事件，事件库 `source_url` 字段通常必须非空且为可访问 URL（http/https，非 `N/A`、非内部路径、非 `mailto:`）；企查查高相关融资按下述明示来源例外执行。
- 阶段 4 评级表中评为 S/A 但 `source_url = N/A` 的企查查条目，必须先完成公开来源补全检索。若仍无结果且直接命中太空算力/太空数据/星载AI/激光通信/宇航级芯片或关键发射链路，可作为 card 例外候选，footer 明示 `Source: 企查查（境内/境外）· 公开来源待补`，禁止伪造链接。
- 这条与"融资 cards ≤ 2"等硬上限并列，参 `reporting-playbook.md` 老板版HTML事件选择规则段。

**2. 来源选择优先级（多来源时显示哪个）**

事件库可能同时有 `source_url`（主来源）+ `secondary_sources`（验证来源）。card 上**只放主来源**作为可点击 footer：

- 优先官方/监管/交易所原文（CNSA / SEC EDGAR / FCC / 巨潮 等 `source_tier = S_Core`）。
- 其次公司 IR / 公司新闻中心。
- 再次 Core 行业媒体（SpaceNews / Payload / Reuters）。
- 最后才是综合财经媒体。

如果阶段 4 评级时主来源用的是低优先级媒体，但 `secondary_sources` 含更高优先级原文，**card 显示阶段 5 时升级为指向 secondary 的更高优先级链接**（同时把 `analyst_note` 标"老板版 card 升级用 secondary"），但不更改事件库主来源记录。

**3. anchor text 写法**

- 默认：`Source: <source_name> ↗`，`source_name` 是事件库字段简称，例如 `SpaceNews` / `FCC` / `21世纪经济报道` / `人民网` / `港交所`。
- 多个来源时只写主来源名，不写 `等多源`。
- 中文媒体名直接用中文（不翻译为拼音/英文）。
- 政府/交易所原文用机构英文缩写：`FCC` / `SEC EDGAR` / `GovInfo` / `CNSA` / `MIIT`，不展开全称。

**4. URL 必须真实可解析（HARD RULE）**

- 不允许编造 / 伪造 URL；不允许把 `https://example.com/`、`#`、`javascript:void(0)` 当 placeholder 提交。
- URL 必须来自事件库 Pass C 验证过的 `source_url` 字段，复制时不得截断或省略 query string。
- 如果 Pass C 验证后 URL 已失效（404 / 403 / 跳转到首页），按上文"来源选择优先级"换一条 secondary；secondary 也失效的，**该事件不得做 card**，从候选名单移除。

**5. 视觉与可访问性**

视觉规范（颜色 / 字号 / hover / focus / dark card 例外）以 `boss-html-design.md` Source Links (HARD MANDATORY) 段为唯一源——本节不重复 token，只规定"内容上必须有"。链接 HTML 形态的最小骨架：

```html
<a href="https://spacenews.com/spacex-sets-date-for-first-starship-version-3-launch/"
   target="_blank"
   rel="noopener noreferrer">Source: SpaceNews ↗</a>
```

**6. 严禁的形态**：

- ❌ 把 source 标记成纯文本（不带 `<a href>`）；
- ❌ 用 `READ MORE` / `阅读原文` / `→` 当 anchor text；
- ❌ 把链接做成 terracotta 填充按钮、card 形状或 pill；
- ❌ 在标题 / lead 句中嵌入 inline 链接（链接固定在 card 底部 footer 位置，与 mono date 同 type token）；
- ❌ 多个来源时把 secondary 也并排列在 card footer——secondary 只在事件库里保留，HTML 上一张 card 一条主链接。

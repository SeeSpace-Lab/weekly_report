# W23 老板版 HTML 固定母版契约

生成或修改老板版 HTML 时，先读 `output-template.md` 与 `reporting-playbook.md` 的老板版段，再读本文件，最后读 `boss-html-design.md`。默认母版是 `assets/老板版_2026-W23.html`。

## 母版权威

- 直接复用 W23 的 `<style>` 内容和 DOM 类名，不重新手写“相似配色”的精简页面。
- 周度变化只进入内容数据：周次、窗口、扫描口径、hero 判断、metrics、proof（含上周重点延伸）、三主线、cards、融资摘要和行动备忘。
- 使用 `scripts/boss_report_w23_renderer.py` 读取母版 CSS；不得复制 CSS 后局部改写。若确需改变视觉体系，先取得用户明确同意并升级母版资产。
- 相邻周导航由渲染器字段 `adjacent_week_href` 与 `adjacent_week_label` 生成；最新一期传 `← W(n-1) 周报`，紧邻历史页传 `W(n) 周报 →`。不得在周度生成器里事后替换 HTML 或追加第二个 `<style>`。

## 不可漂移的七段结构

1. `masthead` + `scanline`
2. 单一 dark `hero`：左侧 claim、右侧 3-5 项 metric rail
3. `proof`：日期列 + 证据列的双栏行，底部直接接单段“上周重点”与构建占位符，不设独立标题
4. `threads`：政策 regulatory ledger、科技 milestone ladder、融资 capital strip
5. `cards`：常规编辑基线 5-8 张，强相关 S/A 全量纳入且数量不限；至少包含 lead、timeline、带 anchor 的 evidence/capital 三类
6. `finsup`：融资其余条目的一段 briefing
7. 三栏 `memo` + 单行 `colophon`

卡片纵向间距、lead 双列正文、timeline 日期侧轨、source link、行动备忘 hairline 等都属于母版结构，不得为了省事扁平化。

## 首屏判断

按“本周事实锚点 → 阶段判断 → 证伪条件”写 50-90 字。至少点出 2 个本周事实或主体，并说明什么证据会确认或推翻判断。避免：

- “本周的分水岭是……”但不说发生了什么；
- “组织、平台与运力开始成形，商业闭环仍待验证”一类可套用到任何周的句子；
- 只复述标题，没有阶段判断或下一验证标准。

## 首屏指标口径

- 必须显示融资占比，并在标签中标明分母。
- 完整版阶段 4 gate 已通过：显示 `融资占正文 X%`。
- 只有老板版 cards 可作为可靠分母：显示 `核心 cards 融资占比 X%`。
- 比例由实际条数计算，例如 `financing_cards / all_cards`，不得手填后长期沿用。
- 其他指标优先：事件表、正文或核心 cards、S/A、政策·科技·融资 split。不要把“来源数”“筛入数”伪装成正文条数。

## Card 判断密度

每张 card 固定四段：`判断 / 影响 / 对我们的意义 / 后续跟踪`。四段分别回答结论、传导路径、可采取动作和可验证触发点。

四个加粗标签与正文之间固定保留一个半角空格，HTML 必须为 `<p><b>判断</b> …</p>`、`<p><b>影响</b> …</p>`、`<p><b>对我们的意义</b> …</p>`、`<p><b>后续跟踪</b> …</p>`。不得让 `</b>` 与正文直接相连。

`后续跟踪` 必须写观察对象 + 指标 + 触发条件，例如“看首批付费客户、可调用算力规模和任务完成时延；没有这些，平台仍只是能力展示”。禁止通用占位句“跟踪后续公告、监管文件、合同落地或技术验证结果”。

## 融资其余条目

当融资事件超过 card 配额时，用一段 180-320 字 briefing：

1. 原始清单总量与筛入数量，分别写境内 `A→B`、境外 `C→D`；
2. 扣除上方融资 cards 后的剩余总量；
3. 用 `<b>` 标出芯片/半导体、商业航天/卫星、AI 算力各自条数；
4. 原币金额置前且不得覆盖，同时给出 RMB/USD 对照金额；第三币种保留原值后再列两种对照值，并在底稿记录汇率日期与来源；
5. 结尾指向数据库版或 `financing_filter_audit_YYYY-Wxx.csv`。

不要写成公司名单、表格或“其余融资见数据库”的空摘要。

## 回归校验

生成后至少验证：

- 输出 `<style>` 与 W23 母版逐字节一致；
- HTML `<title>`、社交分享元数据、masthead 与页面可见文案均不得出现“老板版”；文件名可继续保留内部版本标识；
- cards 常规基线 5-8 张、强相关 S/A 全量纳入且数量不限；至少三种 family，事件较多时避免单一 family 连续重复；
- cards 先完整展示 S 再展示 A；各评级层内按日期升序，同日按政策→科技→融资分组；同类上下相邻但一事一卡；
- 每张 card 四段齐全，四个加粗标签的 `</b>` 后各有一个半角空格，且有 `target="_blank" rel="noopener noreferrer"` 的 source link；
- threads = 3，memo columns = 3，只有一个 dark hero；
- 首屏含融资占比及明确分母；
- 上周重点是 proof 内最后一块且只基于紧邻上一周文件；最新 `index.html` 注入 `← W(n-1) 周报`，紧邻上一周历史页注入 `W(n) 周报 →` 返回首页，更早历史周报不得显示按钮；
- 相邻周链接必须由渲染器直接输出 `previous-button`，目标文件真实存在；未能确认目标时保留 `<!-- PREVIOUS_WEEK_BUTTON -->`，禁止伪造链接。
- 一级板块间距为 65px，核心事件 cards 间距为 48px；
- 融资摘要包含筛入过程、三类条数、金额区间与明细指向。

应用内浏览器若因 `file://` 策略拒绝自动截图，明确报告视觉截图未执行；不得绕过策略，也不得把结构校验说成视觉校验。
